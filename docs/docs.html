RollbackX

Pardus Linux ve Debian tabanlı dağıtımlar için açık kaynaklı sistem snapshot yöneticisi. Tek komutla sistem görüntüsü al, tek komutla geri yükle.

RollbackX; Btrfs, LVM Thin ve Rsync üzerinde çalışan üç farklı backend ile sisteminizin anlık görüntüsünü alır. Yüklemeden önce snapshot alıp güncelleme bozarsa tek reboot ile eski halinize dönersiniz.

💡
Rsync backend herhangi bir ext4/xfs dosya sistemiyle çalışır — özel bir dosya sistemi gerekmez. Btrfs veya LVM varsa onlar otomatik tercih edilir.

CLI Referansı

Tüm yazma işlemleri root yetkisi gerektirir. Listeleme ve bilgi komutları root gerektirmez.

Snapshot İşlemleri

rollbackx snapshot create <isim> [--açıklama <metin>] Yeni bir snapshot oluşturur. --sessiz ile çıktıyı bastır.
rollbackx snapshot list [--json] Tüm snapshot'ları tablo olarak listeler. --json ile makine okunur çıktı.
rollbackx snapshot restore <id> [--zorla] Seçili snapshot'a geri döner ve sistemi yeniden başlatır. --zorla onay sormaz.
rollbackx snapshot delete <id> [--zorla] Snapshot'ı kalıcı olarak siler. Kilitli snapshot silinemez.
rollbackx snapshot info <id> Snapshot'ın tüm detaylarını gösterir (tarih, boyut, backend, kilit durumu).
rollbackx snapshot yeniden-adlandir <id> <yeni-isim> [--aciklama <metin>] Snapshot adını ve açıklamasını değiştirir.

Mount / Gözat

rollbackx snapshot bagla <id> Snapshot'ı /mnt/rollbackx/<id>/ altına read-only bağlar.
rollbackx snapshot ayir <id> Bağlı snapshot'ı ayırır ve mount noktasını temizler.

Kilitleme

rollbackx snapshot kilitle <id> Snapshot'ı kilitler. Kilitli snapshot silinemez veya geri yüklenemez.
rollbackx snapshot kilit-ac <id> Snapshot kilidini kaldırır.

Doğrulama

rollbackx snapshot dogrula <id> Snapshot içindeki kritik sistem dosyalarını kontrol eder. Bozuk snapshot'ları tespit eder.

Otomatik Geri Yükleme

rollbackx oto kur <id> Bir sonraki açılışta belirtilen snapshot'a otomatik geri dönmeyi etkinleştirir.
rollbackx oto kaldir Otomatik geri yüklemeyi devre dışı bırakır.
rollbackx oto goster Aktif otomatik geri yükleme yapılandırmasını gösterir.

Sistem Durumu

rollbackx durum Aktif backend, snapshot sayısı ve toplam disk kullanımını gösterir.

Örnek iş akışı

bash# Güncelleme öncesi snapshot al
sudo rollbackx snapshot create "pre-upgrade-$(date +%F)"

# Güncelle
sudo apt upgrade

# Bir şeyler bozulduysa geri yükle
sudo rollbackx snapshot restore 1

# Sistem yeniden başlar, eski haline döner

Otomatik Geri Yükleme

Belirli bir snapshot'ı "boot snapshot" olarak işaretlediğinizde, bir sonraki önyüklemede sistem o snapshot'a geri döner. Boot devam eder, ekstra reboot olmaz.

  1. Boot snapshot'ı seç
    sudo rollbackx oto kur <id> — veya GTK'dan 🔄 butonuna tıkla.
  2. Sistemi yeniden başlat
    Önyükleme sırasında rollbackx-auto-restore.service otomatik çalışır.
  3. Geri yükleme tamamlanır
    Sistem geri yüklenen dosyalarla açılır. Ayar dosyası silinmez — bir sonraki açılışta da aynı snapshot'a dönülür.
  4. Devre dışı bırak
    sudo rollbackx oto kaldir ile otomatik geri yüklemeyi kapat.
ℹ️
/var/lib/rollbackx/ dizini rsync işleminden hariç tutulur. Snapshot veritabanı ve yapılandırma dosyaları geri yüklemeden etkilenmez.

Backend'ler

RollbackX sisteminizde hangi backend'in kullanılabilir olduğunu otomatik tespit eder. Sıra: Btrfs → LVM Thin → Rsync.

BackendGereksinimAvantajDezavantaj
Btrfs Btrfs dosya sistemi Anlık (CoW), çok hızlı, az disk kullanımı Btrfs gerektirir
LVM Thin LVM Thin pool Block-level CoW, hızlı LVM yapılandırması gerektirir
Rsync Sadece rsync Her dosya sisteminde çalışır (ext4, xfs…) Daha yavaş, tam kopya — daha fazla disk kullanımı

Aktif backend'i görme

sudo rollbackx durum
# Backend: Rsync

Mount / Gözat

Snapshot'ı tam olarak geri yüklemek yerine, sadece birkaç dosyayı kurtarmak istiyorsanız mount özelliğini kullanın. 

bash# Snapshot 3'ü bağla
sudo rollbackx snapshot bagla 3
# → /mnt/rollbackx/3/ adresine read-only bağlandı

# Dosyaları gözat veya kopyala
ls /mnt/rollbackx/3/home/selman/
cp /mnt/rollbackx/3/etc/nginx/nginx.conf ~/nginx-backup.conf

# İşin bitince ayır
sudo rollbackx snapshot ayir 3

GTK arayüzünde "Dosyalarda Aç" butonu bağlar ve Nautilus'u otomatik açar.

⚠️
Mount noktası read-only'dir. Snapshot içindeki dosyaları düzenleyemezsiniz, yalnızca okuyabilir ve kopyalayabilirsiniz.

Snapshot Kilitleme

Kritik bir snapshot'ı yanlışlıkla silmekten veya üzerine geri yüklemekten korumak için kilitleyin. 

bash# Snapshot 1'i kilitle
sudo rollbackx snapshot kilitle 1

# Silmeye çalışırsanız hata alırsınız
sudo rollbackx snapshot delete 1
# → Hata: Snapshot #1 kilitli — silinemez. Önce kilidi kaldırın.

# Kilidi kaldır
sudo rollbackx snapshot kilit-ac 1

Kilitli snapshot'lar listede kilit ikonu (🔒) ile gösterilir. Kilit durumu snapshots.json veritabanında saklanır.

APT Entegrasyonu

RollbackX kurulduğunda APT hook'u otomatik aktif olur. Her apt install, apt upgrade ve apt remove işleminden önce otomatik snapshot alınır. 

/etc/apt/apt.conf.d/80rollbackxDPkg::Pre-Invoke {
  "rollbackx snapshot create 'pre-apt-$(date +%F_%H%M)' --sessiz || true";
};
💡
Hook başarısız olsa bile APT işlemi devam eder (|| true). Snapshot alınamasa da yükleme engellenmez.

Hook'u devre dışı bırakma

sudo rm /etc/apt/apt.conf.d/80rollbackx
